В APK проверены подпись постоянного ключа, versionCode 24, package,

в отчёте. APK не включать в дерево исходников: прикладывать отдельно
как asset GitHub Release.

## Обновление дерева GitHub

Распаковать содержимое source ZIP непосредственно в корень существующего
репозитория рядом с `.git`. Архив уже содержит файлы корня; дополнительную
папку `dvizh/` создавать не нужно. Перед заменой сверить ветку и локальные
изменения с содержимым архива, сохранить изменения, отсутствующие в ZIP.

Затем проверить `git status`, `git diff --check` и staged-файлы. Не добавлять
`key.properties`, `*.p12`, `*.jks`, `*.keystore`, файлы паролей, приватный
архив ключей, APK или сборочные каталоги. Коммитить и отправлять изменения
только после ручной проверки результата слияния.

## Повторная сборка

Среда проверенной сборки: Flutter 3.35.7 / Dart 3.9.2, JDK 17, Android SDK 36.
Постоянный release-ключ хранится отдельно и в ZIP не входит. Восстановить
его файлы по прежней инструкции проекта, затем из `app/` выполнить:

```bash
flutter pub get
ORG_GRADLE_PROJECT_dvizhPreview=false flutter build apk --release \
  --target-platform android-arm64 --build-name=3.10.0 --build-number=24
```

Следующий выпуск должен иметь `versionCode` выше 24. Не отмечать ручную
приёмку завершённой без проверки приложения и виджета на реальном телефоне.
