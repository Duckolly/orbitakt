# Дневной шагомер — ДВИЖ 3.4.0

## Управление

На главной откройте «Шаги за день» и включите переключатель. Требуется системный TYPE_STEP_COUNTER; при его отсутствии остаётся режим отдельных тренировок. Первое показание устанавливает начало отсчёта, ранее накопленные системные шаги не импортируются.

При включённом режиме работает Android foreground service типа health с тихим служебным уведомлением. Остановить можно на экране, действием уведомления или глобальным переключателем записи в настройках. Отказ в уведомлениях не подменяет согласие на подсчёт: запуск происходит только по отдельному действию пользователя. Доступ к физической активности запрашивается при необходимости.

| Состояние | Поведение |
|---|---|
| Экран погашен / другое приложение | Служба сохраняет доступные показания системного счётчика; доставка может задерживаться |
| Окно убрано из недавних | stopWithTask=false; задумано продолжение службы, поведение производителя проверяется на телефоне |
| Переключатель выключен / действие «Остановить» | Приём новых данных блокируется, принятый буфер сохраняется, слушатель отключается, служба останавливается |
| Удаление дневной истории | Подсчёт останавливается, дневные итоги и контрольная точка очищаются; тренировки остаются |
| Удаление всех данных | Останавливаются и очищаются дневной режим, тренировки и настройки |
| ОС завершила процесс | START_STICKY допускает восстановление службой системы; полнота интервала не гарантируется, перезапуск отмечается |
| Принудительная остановка пользователем | Не используется обход остановки; после открытия показано состояние прерывания и кнопка возобновления |
| Перезагрузка | Сохранённая история остаётся, автоматического BOOT_COMPLETED запуска нет; открыть приложение и возобновить |
| Телефон выключен / без питания | Подсчёта нет |

## Связь с тренировками

Если дневная служба уже работает, ходьба/бег наблюдают тот же подтверждённый счётчик через EventChannel. Тренировка ничего не прибавляет в дневную таблицу. Повтор значения не добавляет шагов. При подключении выполняется синхронизация: первое актуальное показание создаёт границу тренировки, старая очередь не импортируется в её счётчик.

Отдельная тренировка по-прежнему ставится на паузу вне приложения; дневной режим продолжает считать. При возобновлении тренировки её граница устанавливается заново, шаги паузы в неё не копируются. Без активной дневной службы используется прежняя программная оценка ускорения. Включение дневного режима посреди такой тренировки не переключает источник её счётчика до следующей тренировки. Даже в таком случае дневная таблица не суммирует программные результаты тренировок.

## Устройство реализации

- `DailyStepService.kt`: SensorManager, foreground health service, уведомление и его Stop-действие.
- `DailyRuntime.kt`: один HandlerThread/актор; сериализация показаний, команд, подписок и остановки.
- `DailyStore.kt`: отдельная приватная SQLite `daily_steps.db`; таблицы `days` и `state`. Исходная БД тренировок не меняется.
- `CounterMath.kt`: расчёт приращений и отсечение старых временных меток.
- `MainActivity.kt`: MethodChannel status/enable/disable/clear и EventChannel общих показаний.
- Dart: DailyScreen, сводка главной, DailyTracker и HardwareWorkoutSensor.

При сохранении в одной транзакции обновляются дневной итог, общий монотонный итог и контрольная точка. Повтор одного системного показания не увеличивает сумму. Смена boot count или уменьшение счётчика создают новую базу без отрицательного приращения. При явном выключении база сбрасывается: шаги выключенного периода не подхватываются следующим включением. Временные метки ранее момента включения отбрасываются, даже если пришли в старой очереди.

## Энергопотребление

Системный счётчик вместо постоянного программного анализа акселерометра. В фоне запрашивается пакетирование до 60 секунд; при открытом приложении/активной тренировке запрос задержки снимается. FIFO и фактические задержки зависят от телефона. Небольшие фоновые пачки записей объединяются через событийную отложенную запись: 500 мс активного времени Android, сон ОС может увеличить задержку; первая база и переданный Stop сохраняются без ожидания. Это событийный таймер, а не постоянный фоновый опрос.

Flutter опрашивает отображаемую историю только в активном интерфейсе; при уходе приложения таймеры UI отменяются. Нативная служба не использует GPS, интернет, WakeLock, периодические WorkManager-задачи или BOOT receiver. Фактическая экономичность на телефоне не измерена; числовых обещаний расхода нет.

## Границы точности и надёжности

Контрольные точки уменьшают потери, но не создают отсутствующие показания. Восстановление после завершения процесса зависит от сохранности системного счётчика и поведения ОС. Редкие пропуски и задержки возможны; «непрерывность» не означает гарантию работы вопреки выключению, перезагрузке и ограничениям производителя.

Дата рассчитывается по временной метке SensorEvent и текущему часовому поясу. Приращение между показаниями разных дат целиком относится к более позднему показанию и помечается приблизительным. Смена часового пояса также отмечается при наличии приращения. Равномерное распределение шагов между днями не выдумывается. Показаны последние 90 записанных дней; более ранние записи сохраняются локально.

Результат сборки и автоматические проверки: VERIFICATION.md. Реальные сценарии заблокированного экрана, Doze, сворачивания, reboot/force-stop и точность — PHONE_ACCEPTANCE.md, пока требуют проверки на устройстве.
